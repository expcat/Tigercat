# i18n

Tigercat uses `locale` objects for component copy and `direction` metadata for RTL. Built-in locale IDs: `en-US`, `zh-CN`, `zh-TW`, `ja-JP`, `ko-KR`, `th-TH`, `vi-VN`, `id-ID`, `es-ES`, `fr-FR`, `de-DE`, `pt-BR`, `ar-SA`. Each built-in pack is a complete object with the same sections and leaves as `en-US`.

## Where Text Lives

| Area                 | Components / files                                                                                                                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Core types           | `packages/core/src/types/locale.ts`                                                                                                                                          |
| Locale packs         | `packages/core/src/utils/i18n/locales/*`, `packages/core/src/utils/i18n/datepicker-locales/*`                                                                                |
| Providers            | Vue and React `ConfigProvider`                                                                                                                                               |
| Localized components | Pagination, Table pagination, DataTableWithToolbar, DatePicker, TimePicker, Modal, Drawer, Upload, FormWizard, TaskBoard, Select, Cascader, TreeSelect, Tree, Marquee, Image |
| Derived components   | Kanban uses TaskBoard, so TaskBoard locale and drag labels apply unless overridden through TaskBoard-compatible props.                                                       |

## Common Labels

The `common` block holds shared defaults reused across many components: `okText`, `cancelText`, `closeText`, `loadingText`, `emptyText`, `searchPlaceholder`, `clearText`, `closeMessageAriaLabel`, `closeNotificationAriaLabel`. In-component search inputs (Tree, Transfer, FileManager) read `common.searchPlaceholder`; Select / Cascader / TreeSelect search, placeholder, clear, Done and loading copy read `locale.select`. AutoComplete / Cascader / TreeSelect empty copy uses `empty.noResults` (not `common.emptyText`). Cascader column names use `select.levelLabel`. Each of these accepts a `locale` prop that merges on top of `ConfigProvider` locale.

## Imports

Prefer subpath imports so bundlers only load the requested language.

```ts
import { zhCN } from '@expcat/tigercat-core/locales/zh-CN'
import { ZH_CN_DATEPICKER_LOCALE } from '@expcat/tigercat-core/datepicker-locales/zh-CN'
```

Vue and React use the same locale object shape.

```vue
<ConfigProvider :locale="zhCN">
  <App />
</ConfigProvider>
```

```tsx
<ConfigProvider locale={zhCN}>
  <App />
</ConfigProvider>
```

DatePicker and Calendar `locale` props take a locale **object** (`zhCN`, a `labels` overlay, or a DatePicker preset). Do not pass `'zh-CN'` — that string does not load copy and must not override ConfigProvider.

Use the registry subpath only when code needs to resolve a built-in DatePicker locale from a runtime string. Importing it pulls in all DatePicker locale presets by design.

```ts
import { getDatePickerLabelsFromLocale } from '@expcat/tigercat-core/datepicker-locales/registry'

const labels = getDatePickerLabelsFromLocale(userLocale)
```

## Async Locale

`ConfigProvider` accepts a locale object, a Promise, or a loader function. During async load, `useTigerConfig()` exposes `localeLoading`. Failures keep the previous or default locale and set `localeLoadError` (development also `devWarn`s). Library components do not read `localeLoading`; gate your own UI if you need a blocking state. `localeLoading` is this provider OR any parent still loading.

```tsx
<ConfigProvider locale={() => import('@expcat/tigercat-core/locales/zh-CN')}>
  <App />
</ConfigProvider>
```

## Text Resolution

Per label, precedence is: dedicated text prop (e.g. Modal `okText`) → component `labels` prop → component `locale` prop → `ConfigProvider` locale → **en-US**. Missing keys never guess language from `locale.locale` or from Chinese sentences. `zh-TW` does not fall back to Simplified Chinese.

Table and DataTableWithToolbar pagination inherit `ConfigProvider` locale. Set `pagination.locale` to override only pagination text, or set `pagination.locale: false` to disable pagination i18n and use explicit pagination text props or built-in English fallback text.

`get*Labels` helpers are `overrides ?? locale.section ?? enUS.section`. Pass the official locale **object** (`zhCN`, `esES`), not a language-id string, when you want translated copy.

## No i18n (Custom Text)

Single-language apps can skip the locale system entirely and just supply their own wording — no locale IDs, no language-pack imports (smaller bundle). Two layers, both optional:

Per component — pass a flat `labels` object (the component's own text fields). Available on Modal, Drawer, Pagination, Select, FormWizard, TaskBoard, Upload (DatePicker/TimePicker already have `labels`).

```tsx
<Pagination total={100} labels={{ totalText: '{total} results', prevPageAriaLabel: 'Previous' }} />
<Select labels={{ doneText: 'Complete' }} />
<Modal open showDefaultFooter labels={{ okText: 'Confirm', cancelText: 'Dismiss' }} />
```

Global — wrap the app once with `ConfigProvider`. Use `defineText(...)` to
author a flat overlay without importing built-in locale packs. It returns only
the supplied text, so omitted fields continue to use en-US.

```tsx
import { defineText } from '@expcat/tigercat-core'

const appText = defineText({ modal: { okText: 'Confirm' }, pagination: { totalText: '{total} items' } })

<ConfigProvider locale={appText}><App /></ConfigProvider>
```

A component `labels` prop overrides global text for that instance. `TigerText`
is the flat type (`TigerLocale` minus `locale`/`direction`). Use
`defineLocale(...)` only for an application overlay on en-US (it fills omitted
keys with English). Built-in packs do not use `defineLocale`.

## RTL

`ar-SA` sets `direction: 'rtl'`. ConfigProvider resolves direction as: explicit `direction` prop → this layer's locale object `direction` → infer from this layer's locale id → parent. `config.direction` and `config.locale.direction` are that same result. Nested `{ locale: 'en-US' }` overlays must be able to switch back to LTR; `mergeTigerLocale` does not copy the parent direction onto a different language.

Only the **outermost** still-mounted ConfigProvider writes `<html dir>`, `data-tiger-dir`, and `lang` (from `locale.locale`). Nested providers only change context. Unmount restores the previous owner or the pre-provider snapshot. A locale-only provider does not strip an existing `<html dir>` / `lang`. Sibling root providers share a stack so the remaining one is not erased.

Pagination and DatePicker mirror navigation icons. Use theme utility classes for custom layout that needs mirroring.

## Add A Locale

When adding a language, update these together:

| Need                 | Files                                                                                           |
| -------------------- | ----------------------------------------------------------------------------------------------- |
| Shared copy          | `packages/core/src/utils/i18n/locales/<id>.ts` (complete object, same leaves as en-US)          |
| Date picker copy     | `packages/core/src/utils/i18n/datepicker-locales/<id>.ts`                                       |
| Date picker registry | `packages/core/src/utils/i18n/datepicker-locales/registry.ts`                                   |
| Package exports      | `packages/core/package.json`                                                                    |
| Build entries        | `packages/core/tsup.config.ts`                                                                  |
| Tests                | `tests/core/i18n-locales.spec.ts` (completeness vs en-US), `tests/core/datepicker-i18n.spec.ts` |

Do not import `defineLocale` from a built-in pack (that pulls en-US + resolvers into the locale entry). Validate with the focused locale tests plus `pnpm build` when export maps or build entries change.
