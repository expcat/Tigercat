# i18n

Tigercat uses `locale` objects for component copy and `direction` metadata for RTL. Built-in locale IDs: `en-US`, `zh-CN`, `zh-TW`, `ja-JP`, `ko-KR`, `th-TH`, `vi-VN`, `id-ID`, `es-ES`, `fr-FR`, `de-DE`, `pt-BR`, `ar-SA`. Each built-in pack is a complete object with the same sections and leaves as `en-US`.

## Common Labels

The `common` block holds shared defaults reused across many components: `okText`, `cancelText`, `closeText`, `loadingText`, `emptyText`, `searchPlaceholder`, `clearText`, `closeMessageAriaLabel`, `closeNotificationAriaLabel`. In-component search inputs (Menu, Tree, Transfer, FileManager) read `common.searchPlaceholder`; Menu empty copy reads `common.emptyText`. Select / Cascader / TreeSelect search, placeholder, clear, Done and loading copy read `locale.select`. AutoComplete / Cascader / TreeSelect empty copy uses `empty.noResults` (not `common.emptyText`). Cascader column, back, expand and collapse copy is `locale.cascader`. TreeSelect uses the same four strings on `locale.treeSelect`. Mentions clear reads `common.clearText`. Each of these accepts a `locale` prop that merges on top of `ConfigProvider` locale.

## Imports

Prefer subpath imports so bundlers only load the requested language.

```ts
import { zhCN } from '@expcat/tigercat-core/locales/zh-CN'
import { getDatePickerLabels } from '@expcat/tigercat-core'
```

Vue and React use the same locale object shape.

```vue
<ConfigProvider :locale="zhCN">
  <App />
</ConfigProvider>
```

```tsx
<ConfigProvider locale={zhCN}>
  <App />
</ConfigProvider>
```

DatePicker and Calendar `locale` props take a locale **object** (`zhCN`, a `labels` overlay, or `{ datePicker }`). Do not pass `'zh-CN'` — that string does not load copy and must not override ConfigProvider. Date copy is `locale.datePicker` inside the same locale object. `getDatePickerLabels(locale)` reads that field. There is no separate `datepicker-locales` import.

## Async Locale

`ConfigProvider` accepts a locale object, a Promise, or a loader function. During async load, `useTigerConfig()` exposes `localeLoading`. Failures keep the previous or default locale and set `localeLoadError` (development also `devWarn`s). Library components do not read `localeLoading`; gate your own UI if you need a blocking state. `localeLoading` is this provider OR any parent still loading.

```tsx
<ConfigProvider locale={() => import('@expcat/tigercat-core/locales/zh-CN')}>
  <App />
</ConfigProvider>
```

## Text Resolution

Per label, precedence is: dedicated text prop (e.g. Modal `okText`) → component `labels` prop → component `locale` prop → `ConfigProvider` locale → **en-US**. Missing keys never guess language from `locale.locale` or from Chinese sentences. `zh-TW` does not fall back to Simplified Chinese.

Table and DataTableWithToolbar pagination inherit `ConfigProvider` locale. Set `pagination.locale` to override only pagination text, or set `pagination.locale: false` to disable pagination i18n and use explicit pagination text props or built-in English fallback text.

`get*Labels` helpers are `overrides ?? locale.section ?? enUS.section`. Pass the official locale **object** (`zhCN`, `esES`), not a language-id string, when you want translated copy.

## No i18n (Custom Text)

Single-language apps can skip the locale system entirely and just supply their own wording — no locale IDs, no language-pack imports (smaller bundle). Two layers, both optional:

Per component — pass a flat `labels` object (the component's own text fields). Available on Modal, Drawer, Pagination, Select, FormWizard, TaskBoard, Upload (DatePicker/TimePicker already have `labels`).

```tsx
<Pagination total={100} labels={{ totalText: '{total} results', prevPageAriaLabel: 'Previous' }} />
<Select labels={{ doneText: 'Complete' }} />
<Modal open showDefaultFooter labels={{ okText: 'Confirm', cancelText: 'Dismiss' }} />
```

Global — wrap the app once with `ConfigProvider`. Use `defineText(...)` to author a flat overlay without importing built-in locale packs. It returns only the supplied text, so omitted fields continue to use en-US.

```tsx
import { defineText } from '@expcat/tigercat-core'

const appText = defineText({ modal: { okText: 'Confirm' }, pagination: { totalText: '{total} items' } })

<ConfigProvider locale={appText}><App /></ConfigProvider>
```

A component `labels` prop overrides global text for that instance. `TigerText` is the flat type (`TigerLocale` minus `locale`/`direction`). Use `defineLocale(overrides, enUS)` for an application overlay. Pass the English table from `@expcat/tigercat-core/locales/en-US` as the base. Built-in packs do not use `defineLocale`. Label helpers still fill missing keys from that English table.

## RTL

`ar-SA` sets `direction: 'rtl'`. ConfigProvider resolves direction as: explicit `direction` prop → this layer's locale object `direction` → infer from this layer's locale id → parent. `config.direction` and `config.locale.direction` are that same result. Nested `{ locale: 'en-US' }` overlays must be able to switch back to LTR; `mergeTigerLocale` does not copy the parent direction onto a different language.

Only the **outermost** still-mounted ConfigProvider writes `<html dir>`, `data-tiger-dir`, and `lang`. `lang` is this layer's locale id, not a locale id inherited from the parent or the English fallback. Nested providers only change context and their own root element. Owners are recorded on the document element: unmount restores the previous living owner, or the snapshot from before the first owner. A locale-only provider does not strip an existing `<html dir>` / `lang`. Unmounting an earlier sibling root does not clear a later root's `dir`.

Pagination and DatePicker follow `dir` and logical properties. Do not mirror layout with physical `left` / `right` overrides.

## Add A Locale

- Packs: `locales/<id>.ts` (complete, same leaves as en-US, including `datePicker`).
- Exports: `packages/core/package.json` + `tsup.config.ts`. Do not `defineLocale` inside a built-in pack.
- Tests: `i18n-locales.spec.ts` / `datepicker-i18n.spec.ts`; `pnpm build` if export maps change.
