# 13 波次与执行顺序

彻底重构，禁止补丁。条目一次做到新结构：不留弃用别名、双写 prop、运行时兼容分支，或只改半边行为的收尾。每个改到的组件，同一批同步 `skills/tigercat` 与 `examples`。测试只在本地跑，不写入 CI / workflow。

## 目标

排定跨文件的执行顺序：工作流正确性提前，发布只做安全窄闸，别名在组件重构当波删除。

## 非目标

不重复各篇任务正文。条数与各篇任务表一起生成，波次以任务表为准。

任务表上的波次是派工标签。硬依赖满足之后就可以开工，不必等前一波里无关条目全部结束。

## 各波在收什么

- **W0 地基单源。** T01 O2、O3、O4、O7、O13、O14、O15。T01 O1 与 T12 O1 同一批拆主入口和样式桶，这一批不挡住表单。方向合同在本波冻结。
- **W1 原语。** 导出消毒、焦点范围、剪贴板、live region、虚拟测量、富文本写入、二维码格式位、校验、上传队列、拖拽会话、水印、代码 token（T01 O5、O6、O8–O11、O16–O21）。
- **W2 协议门、记录与发布安全。** T02 O1 建立 `link-utils`。T07 O1、T09 O3 接着用它。T12 O2–O13 做组件记录、MCP 快照、写盘白名单和发布脚本不变量。T01 O12 删 core 的兼容出口，与记录、基线同一批。
- **W3 表单基础。** T03 全部优化。
- **W4 表单复杂与树。** T04 除 O23 以外的优化；T07 O8、O18、O23。
- **W5 复合正确性。** T11 O3–O18。O1、O2、O19、O20 在 W6。工作流 O5、O6、O7、O18 在 W1 之后即可开工，不等布局和日期控件。O10–O12 仍等 W3，O12 再等 W4 的空值与路径。
- **W6 虚拟窗口与读对数据。** T10 O1、O2、O3、O9、O10；表的导出、时钟、窗口和固定列；图表里会画错的几条（T09 O1、O2、O11、O12、O18）；聊天贴底与长列表（T11 O1、O2、O20）；复合时钟（T11 O19）；T04 O23。
- **W7 反馈浮层。** T05 全部优化。需要 W0 的 scope 和 W1 的焦点范围。
- **W8 其余组件重构。** 基础组件剩余优化、布局、导航剩余、图表剩余、数据表剩余、编辑器与画布。卡片整项在这里做完，href 使用已经存在的 `link-utils`。
- **W9 模块增强。** 各篇增强，除下面点名进 W10 的几条。含 OBS-1、OBS-2、T09 E13、T01 E6。
- **W10 开箱壳与发布面。** T06 E2，T11 E1、E2、E8，T12 E1、E3、E4、E5、E6。
- **W11 preview.1。** 迁移终稿、本地测试、本地四项静态检查、打 `v3.0.0-preview.1`。

## 采纳的顺序修正

- 工作流正确性放在 W5，不排到全部零件优化之后。聊天贴底仍跟在虚拟窗口后面。
- 发布闸是脚本安全不变量加本地静态检查。测试和全量 `quality:release` 留在本地。
- 别名删除不延后到「第二批仍能导入」。它进入组件重构那一波，前提是组件记录已经单源。
