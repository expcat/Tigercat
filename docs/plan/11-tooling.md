# 11 工具链、文档与发布

彻底重构，禁止补丁。条目一次做到新结构：不留弃用别名、双写 prop、运行时兼容分支，或只改半边行为的收尾。每个改到的组件，同一批同步 `skills/tigercat` 与 `examples`。测试只在本地跑，不写入 CI / workflow。

## 目标

- 一条公开组件记录驱动 CLI 白名单、文档 slug、测试分组和 exports。
- 发布脚本拒绝把 tag 拼进 shell，删除和写盘有白名单，Pages `/mcp/` 与所发 tag 同源。
- MCP 默认读与本包一起发布的技能快照。
- 本地测试和本地静态检查是打 `3.0.0-preview.1` 的条件。workflow 不跑这些测试。

## 非目标

- 不把 `quality:release`、覆盖率、示例编译、SSR 冒烟或 e2e 接进 GitHub Actions。
- 不把导出同步、基线 diff、文档 diff、`publish:check` 改成 CI 任务。它们留在本地发布清单。
- 不并行维护第二份组件 schema。
- 正式 Release 的流程不在本篇。W11 只定义 preview。

## 组件记录

扩展 `scripts/lib/public-components.mjs`。它已经导出类别、slug、框架组件表、文档路由和 package exports 的组装函数。3.0 把组件名、类型入口、测试组、示例路径补进同一模块，生成物只从这里来。

不另起 schema 的原因：审查里类别 slug（F349）和 CLI 手写的 57 个名字（F356）已经是两份名单。新文件再生成旧文件，会在切换期变成三份。Ant Design 用 `components/index.ts` 作为公开组件的单一导出清单，文档按这个集合分页。Element Plus 的组件目录同时支撑全量引入和按需解析，避免脚手架与文档站各记一遍。Tigercat 已有的这份模块就是那个角色，所以扩展它，而不是换一个格式再做适配层。

记录先于删名：T12 O5、O7 先长出字段，T12 O8、O9 再生成 exports 和基线。各组件篇里删除别名的任务在该组件重构波次执行，并回写这一份记录。不设「旧名字仍可导入」的过渡发布。

## 发布窄闸

分两半，都要做：

1. **脚本不变量（改 workflow / CLI，随 T12 O2、O3、O4、O10）。** tag 只接受默认分支上、整段匹配的版本，经环境变量传入，不进 shell。去掉从任意分支 `publish --no-git-checks` 的路径。`download-artifact` 失败则任务失败。`rimraf` 只删预置构建目录。CLI 写盘留在目标项目内。`deploy` 把该 tag 的 `/mcp/` 与包放在同一次提交，并带上 O2 要的摘要。远程镜像校验版本与摘要，路径解码后不能离开基址。
2. **本地清单（打 preview 前由人在本机执行，不写入 workflow）。** 导出同步、基线 diff、文档 diff、`publish:check`，加上按 `tests/README.md` 选的测试。T12 O12、O13 要先让这些本地命令认准公开入口，避免缺文件或警告仍以退出码 0 通过。
